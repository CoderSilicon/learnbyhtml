JavaScript: Short, Simple & Slightly Quirky

House analogy, final chapter: HTML = bricks. CSS = paint & furniture. JS = the electricity, the doorbell, and the brain that decides to order pizza at 2 a.m.

Unlike HTML and CSS, JS is a real programming language that can remember, calculate, decide, and react. It's the only one of the three that actually does stuff.

it is an Independent language, which mean it can run on its own without needing to be embedded in an HTML page, So, you can run it standalone and do whatever you do it with other languages like C++, Python, Java, etc. But yeah, it has abundance in websites, So, making or using it websites will be the most popular approach, but not the only one.

1. But How to add?

Where does JS live? Just like CSS, you can write JS inside an HTML file using a <script> ... </script> tag (usually right after </body>), OR in a separate file like app.js connected via <script src="app.js"></script>.

Browsers read HTML by default. A <script> tag is you shouting "Switch brains!"

<body>
  <h1 id="title">Hello!</h1>

  <script>
    // Inline: code lives right here
    console.log("Page loaded!");
  </script>

  <!-- OR external: a separate file, no script tags inside it -->
  <script src="script.js"></script>
</body>
  • Put it at the bottom of <body>. The browser reads top-to-bottom; JS can't grab a button that doesn't exist yet. (Like trying to high-five someone who hasn't arrived.)
  • // = comment. JS ignores it. It's for future-you, who will have zero idea what past-you was thinking.
  • console.log() prints to the Console: right-click → Inspect → Console. Your debugging best friend.

2. Variables: Containers with names

const = a locked safe. Put it in, it's staying there. No changing, or renaming. Use this by default.
let = a cardboard box. Swap the contents whenever (scores, counters).
var = a leaky box from 1995. Do not. It has trust issues and leaks into rooms it shouldn't. 
const userName = "Aarav";  // can't be reassigned
let score = 0;             // can be
score = 10;                // no "let" now, the box already exists
  • = isn't math "equals." It means "take the right side, shove it into the left box."
  • camelCase names: userName, not user_name or USERNAME (unless you're shouting).
  • ; ends the line, like a period. Mostly optional, but be polite.

4. Operators: Math, Comparing, Logic

  • Math: + - * / do what you'd expect. % = remainder (10 % 3 is 1; n % 2 === 0 means even). ** = power (2 ** 3 is 8). score++ = add 1.
  • The classic trap: "5" + 2 is "52". If a string is involved, + glues instead of adds. JS is not sorry.
  • Compare: === (same value and type), !==, > < >= <=. Always use three equals. "5" === 5 is false. Two equals (==) means only the value, is how bugs are born.
  • Logic: && = AND (both true), || = OR (at least one), ! = NOT (flip it).

5. Decisions: if / else if / else

A fork in the road. JS checks conditions top to bottom and takes the first true one.

const battery = 15;

if (battery <= 10) {
  console.log("Plug in NOW");
} else if (battery <= 25) {      // 15 <= 25 is true, so this runs
  console.log("Low battery");
} else {                          // fallback: no condition needed
  console.log("You're fine");
}

// One-line version (ternary): condition ? ifTrue : ifFalse
const msg = battery < 20 ? "Charge soon" : "All good";
Reading it out loud: "If it's dire, panic. Else if it's meh, worry a bit. Else, chill."

if is an independent keyword which means you can use only if statements if you want.

if(condition) { // code to execute if condition is true }

But else if and else are not independent and cannot be use solely. Just use common sense, if you don't have any if then how would you reach to else? Not possible in spoken languages too, :D

6. Loops: Repeat Without Copy-Paste

Need to print "Hello" 100 times? You could type 100 lines and ruin your weekend. Or you write one block and tell JS how many times to run it. That's a loop.

Every loop is the same 3 questions: Where do I start? When do I stop? How do I get closer to stopping? Mess up the third one and your tab becomes a very expensive space heater.

A. The for loop: when you know the count

for (let i = 1; i <= 3; i++) {
  console.log("Jump #" + i);
}
// Output: Jump #1, Jump #2, Jump #3

Anatomy: three parts inside the parentheses, separated by semicolons, then a body in curly braces.

Part Code Runs... Job
Start let i = 1 Once, before anything Creates the counter box i
Check i <= 3 Before every lap true = go in. false = loop is over
Body { ... } Each lap that passed the check The work you want repeated
Update i++ After the body, every lap Moves the counter toward the finish line

Lap-by-lap trace (this is the part that makes it click):

Lap i now Check i <= 3 Body prints Update
1 1 true Jump #1 i becomes 2
2 2 true Jump #2 i becomes 3
3 3 true Jump #3 i becomes 4
(end) 4 false nothing loop exits, JS moves on
Notice the order: start, check, body, update, check, body, update, check (fails), exit. The update runs after the body, and the check always runs before it. Read that sentence twice. It's 90% of loops.

Start, check, and update are yours to bend:

for (let i = 10; i > 0; i -= 2) {   // count DOWN by 2s
  console.log(i);                    // 10, 8, 6, 4, 2
}

let total = 0;                       // loops love building up a result
for (let i = 1; i <= 5; i++) {
  total += i;                        // total = total + i
}
console.log(total);                  // 15  (1+2+3+4+5)
  • i -= 2 means "subtract 2 from i". Same family as +=, *=, /=.
  • Declare the accumulator (total) outside the loop. Declare it inside and it resets to 0 every lap, like a goldfish with a calculator.
  • The counter must be let, not const. i++ changes it, and a locked safe doesn't like that (you'll get a TypeError).

B. The while loop: when you only know the stopping rule

let coins = 3;                          // START: you write this yourself, before the loop
while (coins > 0) {                     // CHECK: before every lap
  console.log("Playing arcade...");     // BODY
  coins--;                              // UPDATE: you write this yourself, inside the body
}

A while loop is a for loop with the three parts spread out. Only the check lives in the parentheses. Start goes above, update goes inside. Nobody does the update for you.

Lap coins now Check coins > 0 Body
1 3 true prints, then coins becomes 2
2 2 true prints, then coins becomes 1
3 1 true prints, then coins becomes 0
(end) 0 false loop exits
The Infinite Loop: delete coins-- and coins stays 3 forever. 3 > 0 is always true. The loop never ends, the page freezes, and your laptop fan starts auditioning for a jet engine. Every programmer has done this. Anyone who says they haven't is lying or lucky.

Another classic while use: loop until something happens, when you have no idea how many laps that takes.

let rolls = 0;
let dice = 0;
while (dice !== 6) {                    // keep rolling until we get a 6
  dice = Math.floor(Math.random() * 6) + 1;
  rolls++;
}
console.log("Got a 6 after " + rolls + " rolls");

C. The for...of loop: walk through a list

const snacks = ["Chips", "Apple", "Cookie"];

for (const item of snacks) {
  console.log(item);                    // Chips, Apple, Cookie
}

// The older "index" way: same result, more typing
for (let i = 0; i < snacks.length; i++) {
  console.log(snacks[i]);               // start at 0, stop BEFORE length
}
  • for (const item of snacks) reads as "for each item in snacks". No counter, no check, no update. JS handles all of it.
  • const works here because each lap gets a brand-new item box. It's not being changed, it's being recreated.
  • In the index version, arrays start at 0, so i < snacks.length (strictly less than). Using <= gives you one lap too many and an undefined at the end.
  • Default to for...of for lists. Use the classic for when you need the position number or want to count by something other than 1.

D. Emergency controls: break and continue

for (let i = 1; i <= 10; i++) {
  if (i === 3) continue;   // skip THIS lap only, jump to the next one
  if (i === 6) break;      // abandon the whole loop right now
  console.log(i);          // prints: 1, 2, 4, 5
}
  • continue = "Not this one." Skips the rest of the body, then the update and check still happen.
  • break = "I'm out." Exits the loop completely. It's also the escape hatch for a while loop you can't easily write a clean check for.

E. Loops inside loops (nested)

for (let row = 1; row <= 3; row++) {          // outer: 3 laps
  for (let col = 1; col <= 3; col++) {        // inner: 3 laps PER outer lap
    console.log(row + " x " + col + " = " + row * col);
  }
}
// 3 x 3 = 9 lines total

Think of a clock: the minute hand does a full circle for every single tick of the hour hand. The inner loop finishes completely before the outer loop moves one step. Total laps = outer laps × inner laps. Nest too deep and a "small" loop becomes billions of laps.

Which loop do I use?

Situation Use Why
"Do this exactly N times" for Counter, check, and update all in one line
"Do something with every item in a list" for...of Simplest, fewest ways to mess up
"Keep going until something happens" while You don't know the lap count in advance
"Skip one / quit early" continue / break Works inside any of the above

The 4 classic loop bugs

  • Off-by-one: i < 3 runs 2 laps from 1 (or 3 from 0). i <= 3 runs 3 from 1. Pick on purpose, and trace the first and last lap.
  • No progress: forgetting i++ or coins--. Infinite loop.
  • Wrong direction: for (let i = 1; i <= 3; i--). i goes 1, 0, -1, -2... and is always <= 3. Infinite loop with extra steps.
  • Wrong box: declaring total inside the loop (resets every lap) or the counter as const (crashes on update).

7. Functions: Reusable Mini-Machines

A function is a juicer. Build it once. Drop in fruit (parameters), blades spin, juice comes out (return). You never rebuild the juicer to make a second glass.
function addTax(price, taxRate = 0.1) {   // 0.1 = default if you skip it
  return price + price * taxRate;         // return = hand back the result & stop
}
const bill = addTax(100);                 // () = turn the machine ON → 110

// Arrow function: same thing, tiny
const double = (x) => x * 2;              // one expression = auto-return
console.log(double(5));                   // 10

Defining a function builds the machine. Calling it (name()) presses the button. Beginners forget the button.

8. Arrays & Objects: Lists vs. Profiles

Arrays [ ]: ordered lists

Golden rule: JS counts from 0. First item is #0. Programmers aren't being weird, they're counting distance from the start.
const snacks = ["Chips", "Apple", "Cookie"];
snacks[0];            // "Chips"
snacks.push("Donut"); // add to end

for (const item of snacks) console.log(item);

[1, 2, 3].map(n => n * 2);          // [2, 4, 6]  transform every item
[1, 2, 3, 4].filter(n => n > 2);    // [3, 4]     keep only winners

Objects { }: one thing, many labels

const player = { name: "Nullstroke", level: 5, isOnline: true };
player.name;       // "Nullstroke"
player.level = 6;  // update

const { name, level } = player;  // destructuring: unpack in one line

9. The DOM & Events: JS Meets HTML

When a page loads, every HTML tag becomes a live JS object. That tree of objects is the DOM. Grab one, change it, react to clicks.

const btn = document.querySelector("#demo-count-btn"); // same #id / .class as CSS
const box = document.querySelector("#demo-dom-output");

btn.addEventListener("click", () => {   // "wait for a click, then run this"
  box.textContent = "You clicked!";     // change the text
  box.classList.toggle("party");        // add CSS class if missing, remove if there
});

Other events: "input" (typing), "mouseover" (hover), "keydown" (keys).

10. Async: Don't Freeze the Page

JS has one worker. If it stood around waiting for the internet, the whole page would freeze. So fetch() hands you a Promise: a restaurant buzzer. await = "wake me when the pizza's ready", while everything else keeps working.
async function getWeather() {
  try {
    const res  = await fetch("https://api.example.com/weather");
    const data = await res.json();       // JSON text → JS object
    console.log(data.temperature);
  } catch (err) {
    console.log("Internet said no:", err);
  }
}
